# Architecture — KeywordAI

## Project Snapshot

- **Purpose:** AI-powered keyword validation and clustering tool for Google Ads freelancers. Users pick a keyword CSV and describe their campaign; the app cleans the data, evaluates relevance via Gemini, and clusters the results into ad group themes.
- **Stack:** Go 1.24 · Wails v2 · SvelteKit 2 (SSR off, prerendered SPA) · Svelte 5 · Skeleton UI v4 · Tailwind CSS · `@lucide/svelte` · Google Gemini API (`google.golang.org/genai`)
- **Entry point:** `main.go` → `wails.Run(...)` → Wails creates the window → calls `app.setupBackend(ctx)` on startup
- **Runs as:** native desktop app (single binary, embedded frontend). No HTTP server, no Docker.
- **Configuration:** `GEMINI_API_KEY` loaded from `.env` on startup (fallback). Settings feature (planned) will replace this with `~/.config/keywordai/config.json`.

## Core Patterns

### 1. Wails command binding

- **What it is:** Go structs are registered in `main.go`'s `Bind` slice. Wails generates TypeScript bindings in `frontend/src/lib/wailsjs/go/`. The frontend calls Go methods directly — no HTTP, no fetch.
- **Why it is used here:** Eliminates the HTTP server entirely. The desktop app has no port, no routing layer, and no CORS. Go methods are called like local async functions.
- **Where to see it:** `main.go` `Bind: []interface{}{app.Backend.Keywords, app.Backend.Upload}` · `frontend/src/lib/wailsjs/go/keywords/` (auto-generated)
- **Rule for new features:** Create a new command struct under `backend/commands/[feature]/`. Add it as a field on `Backend` in `backend/backend.go`. Wire its `Setup()` call there. Register it in `main.go`'s `Bind` slice. **Bind individual command structs, not the `App` or `Backend` struct** — each entry becomes a separate import namespace in the frontend.
- **Important:** The Wails context (`ctx` from `OnStartup`) is needed for runtime calls like `OpenFileDialog`. Store it in the command via a `Setup(ctx)` method. Never call `runtime.*` without a valid context.

---

### 2. Async job + frontend polling

- **What it is:** A Go method creates a UUID job, launches a goroutine, and returns the job ID immediately. The frontend calls a status method every second (via `setInterval`) until the job reaches `completed` or `failed`.
- **Why it is used here:** Gemini calls take 5–30 seconds. Blocking the Wails call for that duration would freeze the UI. The job manager decouples the call (instant) from the work (async).
- **Where to see it:** `backend/commands/keywords/keywords.go` — `StartEvaluation` / `StartClustering` create jobs and launch goroutines. `frontend/src/routes/keywords/+page.svelte` — `poll()` helper calls `GetEvaluationStatus` / `GetClusterStatus` every 1 second.
- **Rule for new features:** Any Go call that may take more than ~2 seconds must use this pattern. `CreateJob()` → goroutine → `CompleteJob(id, payload)` or `FailJob(id, errMsg)`. **Always call `FailJob` on every error path** — a missing call leaves the job in `StatusProcessing` and the spinner never stops. The frontend `poll()` helper in the keywords page can be extracted to a shared utility if multiple pages need it.

---

### 3. Composable pipeline with typed steps

- **What it is:** Data cleaning is expressed as an ordered `[]pipeline.Step` slice. Each step receives `*pipeline.Context{Headers, Rows}`, transforms it in place, and returns an error to abort. `pipeline.Run()` executes in order.
- **Why it is used here:** Adding, removing, or reordering a cleaning step is a one-liner change to the step slice in `ProcessKeywords`. Generic steps live in `pipeline/steps.go` and are reusable by any future processor. Domain-specific steps (AI validation) stay in the processor package.
- **Where to see it:** `internal/pipeline/pipeline.go` · `internal/pipeline/steps.go` · `internal/processor/keywords.go` step slice.
- **Rule for new features:** Generic CSV transformations → `pipeline/steps.go`. Feature-specific steps with external dependencies → feature's processor package. Steps always receive and mutate the same `Context` shape — never change `Context`.

---

### 4. Source abstraction

- **What it is:** `internal/source/KeywordSource` is an interface: `Open() (io.ReadCloser, error)` + `Cleanup() error`. `CSVFileSource` implements it for the tmp-file case. The processor calls `Open()` and defers `Cleanup()`.
- **Why it is used here:** Decouples the processor from the file system. A future Google Ads API source implements the same interface; `ProcessKeywords` changes nothing.
- **Where to see it:** `internal/source/source.go` · `internal/processor/keywords.go` defer block.
- **Rule for new features:** Any new data input (API, database query, clipboard) implements `KeywordSource`. The processor receives the interface — never a raw file path or `*os.File`.

---

### 5. AI interfaces over concrete types

- **What it is:** `internal/ai/ai.go` defines `KeywordEvaluator`, `KeywordGenerator`, and `KeywordOrganizer` interfaces. `KeywordsCommand` holds `ai.KeywordEvaluator` and `ai.KeywordOrganizer` — not `*ai.Client`. Processors accept the narrowest interface they need.
- **Why it is used here:** Swapping Gemini for OpenAI (or a test stub) requires implementing the interface — no command or processor code changes.
- **Where to see it:** `internal/ai/ai.go` · `backend/commands/keywords/keywords.go` struct fields · `internal/processor/keywords.go` `KeywordProcessParams.Evaluator`.
- **Rule for new features:** Never accept `*ai.Client` in a command or processor. Accept the interface. Add new interfaces to `ai.go` for new AI capabilities.

---

### 6. SvelteKit state machine

- **What it is:** Each page that has multiple distinct UI phases (form → loading → results → ...) declares a `phase` variable using Svelte 5's `$state` rune. A `{#if phase === '...'}` block renders the correct component. Phase transitions are driven by async function results.
- **Why it is used here:** Provides a clear, auditable view of every possible screen state without a router or external state library. Adding a new phase is a one-liner: add the string literal to the `Phase` type union and a new `{:else if}` block.
- **Where to see it:** `frontend/src/routes/keywords/+page.svelte` — `type Phase = 'form' | 'evaluating' | 'results' | 'clustering' | 'clustered' | 'error'`
- **Rule for new features:** Each tool gets its own route under `src/routes/[tool]/`. The page owns the state machine. Components (`KeywordForm`, `KeywordTable`, etc.) are stateless and receive data via props + callback props (`onSubmit`, `onCluster`, `onReset`).
- **Svelte 5 gotchas:** `$derived` requires `let`, not `const`. `$state` is initialized once — do not use `$effect` to sync it from DOM if the DOM attribute is already correct at render time (the LightSwitch bug).

## Data Flow

```
1. App startup
   main.go → wails.Run() → window created
           → app.setupBackend(ctx) called
           → backend.go: initLogger, loadDotEnv, ai.NewClient(ctx),
             jobs.NewManager(), b.Keywords.Setup(...), b.Upload.Setup(ctx)
           → SvelteKit app loads in the embedded webview

2. File selection
   User clicks "Choose CSV" in KeywordForm
        → frontend calls Upload.PickAndSaveCSV() (Wails binding)
        → Go: runtime.OpenFileDialog(ctx, ...) — native OS file picker
        → user picks file; Go copies it to tmp/<filename>
        → returns filename string to frontend
        → form stores filename, enables Submit button

3. Evaluation start
   User fills form, clicks Submit
        → frontend calls Keywords.StartEvaluation(EvaluationParams)
        → Go: jobs.Manager.CreateJob() → UUID job ID
        → Go launches goroutine: processor.ProcessKeywords(...)
        → returns JobRef{JobID} immediately
        → frontend phase = 'evaluating', starts poll(jobId, GetEvaluationStatus, ...)

4. Evaluation (background goroutine)
   processor.ProcessKeywords(KeywordProcessParams)
        → defers CSVFileSource.Cleanup()  (tmp file deleted on return)
        → source.Open() → ParseCSVToSlice()
        → DropUnwantedColumns (no-op), ExtractHeaderRow
        → copies rows to originalRows
        → pipeline.Run(ctx, steps):
            RemoveEmpty{}          (drop all-blank rows)
            DropIfEmpty{col:0}     (drop rows with no keyword)
            Deduplicate{col:0}     (case-insensitive dedup)
            ExcludeRows{terms,0}   (user exclusion list)
            aiValidationStep{}     (Gemini EvaluateKeywords call)
        → ZipResults (merge original + AI columns)
        → jobs.Manager.CompleteJob(id, KeywordJobPayload{Header, Content, OriginalRows})
        on any error → jobs.Manager.FailJob(id, err.Error())

5. Polling (evaluation)
   Frontend setInterval every 1s → Keywords.GetEvaluationStatus(jobId)
        → StatusProcessing: continue polling
        → StatusCompleted: phase = 'results', render KeywordTable
        → StatusFailed: phase = 'error', render error card

6. Cluster start
   User checks rows in KeywordTable, clicks "Proceed to Clustering (N)"
        → frontend calls Keywords.StartClustering({evalJobId, selectedRows})
        → Go: reads eval job payload, filters to selected row indices
        → jobs.Manager.CreateJob() → new UUID
        → launches goroutine: processor.ProcessClustering(...)
        → returns JobRef{JobID}
        → frontend phase = 'clustering', starts poll(jobId, GetClusterStatus, ...)

7. Clustering (background goroutine)
   processor.ProcessClustering(ClusterProcessParams)
        → AI.OrganizeKeywords(ctx, "", headers, rows)  (Gemini clustering call)
        → ZipResults (merge eval columns + Cluster column)
        → jobs.Manager.CompleteJob(id, ClusterJobPayload{Header, Content, OriginalRows})
        on any error → jobs.Manager.FailJob(id, err.Error())

8. Polling (clustering)
   Frontend setInterval every 1s → Keywords.GetClusterStatus(jobId)
        → StatusCompleted: phase = 'clustered', render ClusterResults
        → StatusFailed: phase = 'error'
```

## Adding a New Feature (Tool)

1. **Go backend:** Create `backend/commands/[feature]/[feature].go`. Define a command struct holding only the deps it needs (`*jobs.Manager`, relevant AI interface).
2. Add a `Setup(...)` method on the struct that receives deps.
3. Add the command as a field on `Backend` in `backend/backend.go`. Wire `Setup()` in `Backend.Setup()`.
4. Register the command in `main.go`'s `Bind` slice.
5. **Frontend route:** Create `frontend/src/routes/[feature]/+page.svelte`. Define a `Phase` union type and a `$state<Phase>` variable.
6. **Components:** Create stateless Svelte components in `frontend/src/lib/components/`. Pass data via props; actions via callback props (`on[Action]`).
7. **Homepage:** Add a new card to `frontend/src/routes/+page.svelte` linking to the new route.
8. **Async work:** Any Go call > ~2 seconds must use `CreateJob` → goroutine → `Complete/FailJob`. Mirror the `poll()` pattern from the keywords page.
9. **Documentation:** Create `docs/features/[FeatureName].md` before writing code.

## Modifying an Existing Feature

1. Read `docs/features/[FeatureName].md` to understand the original intent.
2. Read the relevant source files — do not rely on memory.
3. **If the change affects a Go method signature on a bound command:** update the frontend Wails binding imports (the generated files in `wailsjs/go/` update automatically on next `wails build`/`wails dev` run, but callers need updating).
4. **If the change affects the `[][]string` data shape:** the pipeline steps, AI layer, job payload, and frontend types all need updating simultaneously.
5. **If adding/removing a pipeline step:** edit only the step slice in `ProcessKeywords` — existing steps are unchanged.
6. After the change: verify the Data Flow section above still holds end-to-end.
7. Update `docs/features/[FeatureName].md` with a Change History entry.

## Constraints

- **Wails is the only integration layer.** Do not add an HTTP server alongside it. All Go↔frontend communication is via bound command methods.
- **`[][]string` is the internal data contract.** Header row + data rows is how every layer exchanges data. Changing this shape touches pipeline steps, the AI layer, and job payload at once.
- **The async job pattern is required for operations > ~2 seconds.** Never block a Wails-bound method with long-running work.
- **Always call `FailJob` on every processor error path.** A missing call leaves the job in `StatusProcessing` and the spinner spins forever.
- **New data sources implement `source.KeywordSource`.** Do not pass file paths as strings into the processor.
- **New AI calls use the narrowest interface from `ai.go`.** Do not accept `*ai.Client` in commands or processors.
- **`frontend/src/lib/wailsjs/` is auto-generated.** Never edit files in that directory — they are overwritten by `wails build`/`wails dev`.
- **File dialog must be opened from the Go side.** `runtime.OpenFileDialog` is a Go runtime function. It is not exposed in the frontend Wails JS runtime. Always invoke it via a bound command method.
- **SvelteKit is configured as a pure client-side SPA** (`ssr = false`, `prerender = true`). Do not enable SSR — there is no server to run it.
- **No database before you need one.** In-memory job manager is correct for desktop single-user use. SQLite is the planned path when persistence is needed.
